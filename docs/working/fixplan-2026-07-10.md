## WP1: BigInt-safe models JSON parsing (F6, F7, S4)

**Problem recap:** `parseWithBigInts` (`src/anki/util.ts`) never matches its
target paths for the real `col.models` shape (dict keyed by model id), so
(a) 64-bit template/field ids silently lose precision on **every** read —
including direct Anki→Anki operations, confirmed against the repo's own
`mixed-legacy-2.apkg` fixture — and (b) _any_ digit-only string value in
models JSON is coerced to a `Number` (a field named `"2024"` exports as
`"name":2024`; a note type named `"007"` is destroyed together with its
notes and cards).

**Fix (per D3):**

1. Add a new util, e.g. `parseJsonWithBigInts(jsonString: string): unknown`:

   ```ts
   export function parseJsonWithBigInts(jsonString: string): unknown {
     return JSON.parse(jsonString, (_key, value, context?: { source?: string }) => {
       if (
         typeof value === "number" &&
         !Number.isSafeInteger(value) &&
         context?.source !== undefined &&
         /^-?\d+$/u.test(context.source)
       ) {
         return BigInt(context.source);
       }
       return value;
     });
   }
   ```

   Pitfalls to preserve in the implementation:
   - The `/^-?\d+$/` source guard is load-bearing: `Number.isInteger(1e21)`
     is `true` but `BigInt("1e21")` throws. Only convert plain integer
     literals.
   - `context.source` exists only for primitive values and only on V8 ≥ 11.8
     (Node ≥ 21). Engines floor is 22, so it's safe; still return `value`
     unchanged if `context?.source` is `undefined` rather than crashing.
   - TypeScript's lib may not declare the third reviver parameter — a local
     type assertion on the reviver is acceptable.
   - Strings are **never** touched (fixes F7 by construction).
   - Negative literals work (the old regex quoting missed them).

2. Replace the call in `src/anki/database.ts` `getCollection()`
   (`parseWithBigInts(collectionRaw.models, ["tmpls[].id", "flds[].id"])`)
   with `parseJsonWithBigInts(collectionRaw.models)`.
   Consequence: any unsafe integer anywhere in models JSON (including
   plugin keys) becomes `bigint` at runtime; `serializeWithBigInts` on the
   write path emits it back as a bare literal, so write fidelity is
   preserved. Type-wise only `Template.id`/`Field.id` are declared
   `bigint | null` — that stays; other locations are `number` and will in
   practice stay `number` (mod/usn/ids are all < 2^53).

3. Delete `parseWithBigInts`, `validateTargetFieldsAreNumeric`,
   `getValuesAtPath`, `quoteNumbersForFieldName`,
   `processValueWithPrecisePaths` and their tests in `util.test.ts`
   (~300 lines). Nothing else imports them (verify with a grep before
   deleting).

4. Harden `serializeWithBigInts` against S4 (marker collision): before the
   final `replaceAll`, check whether the _input_ already contains the marker
   pattern; if so, switch to a nonce-based marker
   (`__BIGINT_<random>_…`) regenerated until absent from the serialized
   string. Keep the function's signature.

**Regression tests (port from audit repros `03-unit.audit.ts` /
`02-direct.audit.ts`, inverted to assert correctness):**

- `parseJsonWithBigInts` on a models-shaped dict with
  `"id":6134417914424963362` and `"id":-8113853199325282904` → `bigint`
  values, exact.
- Field named `"2024"` stays a **string** through read → write.
- Note type named `"007"` survives `fromAnkiExport` (status `success`, name
  `"007"`).
- Direct round-trip of `tests/fixtures/anki/mixed-legacy-2.apkg`: the six
  large id literals in the output models JSON are byte-identical to the
  source (compare with a regex on the raw column string — a JS
  `JSON.parse`-based comparison would mask the loss).
- `serializeWithBigInts` round-trips a string value literally containing
  `__BIGINT__123__BIGINT__`.

**Acceptance:** all of the above green; `pnpm test` green; old helpers gone.

## WP2: Full-fidelity blob capture & restore (F1, F2, F4, F5, F11, F12, F13, F14, F17, F18, S3)

**Problem recap:** `toSrsPackage` captures almost nothing beyond ids and
content; `fromSrsPackage` rebuilds every entity from hardcoded defaults.
Scheduling state, revlog details, guids, tags, note-type internals, deck
options, `col` metadata, and `graves` are all silently lost. The existing
`ankiGuid`/`ankiTags`/`ankiDeckData`/`ankiTemplateData`/`ankiDue`/`ankiQueue`/
`ankiType` keys are write-only.

**Fix (per D1): capture full rows, restore with overlay.**

### Capture (in `toSrsPackage`)

Store one blob key per entity in `applicationSpecificData`, serialized with
`serializeWithBigInts` (WP1 makes this safe for 64-bit ids):

| Entity    | New key        | Content                                                                                     |
| --------- | -------------- | ------------------------------------------------------------------------------------------- |
| note      | `ankiNote`     | full `NotesTable` row                                                                       |
| card      | `ankiCard`     | full `CardsTable` row                                                                       |
| review    | `ankiReview`   | full `RevlogTable` row                                                                      |
| deck      | `ankiDeck`     | full deck JSON (already exists as `ankiDeckData` — rename or keep name, but **restore it**) |
| note type | `ankiNoteType` | full model JSON incl. plugin keys                                                           |
| package   | `ankiCol`      | `col` scalars (`crt`, `mod`, `scm`, `dty`, `usn`, `ls`) + `conf` + `tags`                   |
| package   | `ankiDconf`    | full `dconf` JSON                                                                           |
| package   | `ankiGraves`   | `graves` rows                                                                               |

Package-level keys require a new optional
`applicationSpecificData: Record<string, string>` on `SrsPackage` itself
(plus getter/setter). This is an additive format change; document it in the
ADR-0003 update (WP7).

Keep `originalAnkiId` (id resolution depends on it) and keep the documented
`ankiData` key (user-facing plugin-data override, see restore precedence).
Drop the now-redundant `ankiGuid`, `ankiTags`, `ankiDue`, `ankiQueue`,
`ankiType`, `ankiTemplateData` keys — alpha software, but update the docs
pages that mention them (WP7).

### Restore (in `fromSrsPackage`) — overlay precedence

General rule: **parse the blob as the base row; overlay the fields the
universal format owns (SRS wins); remap all cross-references to the new ids.**
If a blob is missing or unparseable → fall back to today's defaults and emit
a _warning_ issue (never throw).

Per entity, SRS-authoritative fields (overlay wins):

- **note:** `id` (via `resolveAnkiId` + bump loop), `mid` (mapped),
  `flds` (from `fieldValues`), `sfld` (recomputed, F17: HTML-stripped
  content of the field at the model's `sortf`, fallback field 0), `csum`
  (recomputed always, F14: first 8 hex digits of SHA1 of the HTML-stripped
  **first** field — `node:crypto`, see `pylib/anki/utils.py:fieldChecksum`),
  `data` (`ankiData` key wins if present, else blob's `data`, else `""`).
  Everything else (guid F4, tags F5, mod/usn/flags F14) from blob.
  No blob → today's behavior plus computed `csum`/`sfld`, fresh `guid64()`.
- **card:** `id`, `nid`, `did` (all remapped — blob values are the
  _original_ ids; never write them through), `ord` (from SRS
  templateId/cloze logic), `data` (`ankiData` precedence as above).
  Everything else — `type`, `queue`, `due`, `ivl`, `factor`, `reps`,
  `lapses`, `left`, `odue`, `odid`, `flags`, `mod`, `usn` (F1) — from blob.
- **review:** `id` (resolve + **bump loop**, coordinate with WP5/F16),
  `cid` (remapped), `ease` (from SRS `score` — user may have edited it).
  `ivl`, `lastIvl`, `factor`, `time`, `type`, `usn` (F2) from blob.
- **deck:** `id` (resolved), `name`, `desc` from SRS. Everything else
  (`conf`, limits, counters, `dyn`, collapse state, plugin keys — F12) from
  blob.
- **note type:** `id` (resolved), `name` from SRS; field names/descriptions
  and template names/`qfmt`/`afmt` from SRS **matched by position**; blob
  supplies everything else (css, latex, `latexsvg`, `sortf`, `req`,
  `originalStockKind`, `type`, template `bqfmt`/`bafmt`/`did`/`bfont`/
  `bsize`/64-bit `id`, field props, plugin keys — F11, F18).
  Structural drift rule: SRS structure is truth — if SRS has more
  fields/templates than the blob, generate defaults for the extras; if
  fewer, drop the blob extras.
  No blob (SRS-authored): keep today's defaults **except**
  `req: templates.map((t, i) => [i, "any", [0]])` and
  `originalStockKind: null` instead of the hardcoded single-entry req / `1`
  (F18).
- **package (`col`):** restore `crt`, `conf`, `tags` from `ankiCol`;
  `dconf` from `ankiDconf`; `graves` from `ankiGraves` (F13). Force
  `ver: 11` and `id: 1` regardless of blob. **`crt` and card `due`/`queue`
  must come from the same source** — restoring one without the other shifts
  every review due date; this is why F1 and F13 are one WP.

### S3 while you're in there

`toSrsPackage` currently maps `flds`/`tmpls` by array index. Sort both
arrays by their `ord` property before mapping (stable, `ord` ascending) so a
mis-sorted models JSON cannot remap content. Card `ord` values already refer
to template `ord`, not array position.

**Regression tests:**

- Port the audit's adversarial-apkg builder (`helpers.ts` in
  `docs/working/audit-2026-07-10-repros.md`) into the test fixtures, then
  invert the `01-roundtrip.audit.ts` assertions: after round-trip, notes /
  cards / revlog / decks / dconf / conf / crt / graves must be semantically
  identical to the source (the audit doc's Appendix A table is the
  checklist — every ❌/✳ row becomes a ✅ assertion).
- Overlay tests: rename a deck and edit a field value in SRS before
  converting back → new name/content present, scheduling/guid/tags still
  restored from blob.
- Corrupt blob test: garbage in `ankiCard` → warning issue + default card,
  conversion still succeeds.
- SRS-authored (no blobs): csum is a real checksum, `sfld` set, `req` has
  one entry per template, `originalStockKind` null.

**Acceptance:** round-trip of the adversarial package is lossless for every
field in Appendix A except explicitly SRS-owned overlays; all statuses
`success`; no silent fallbacks (every fallback emits a warning).

## WP3: Cloze parity (F9, S1, S2)

**Problem recap:** the ordinal regex can't match `}` inside cloze bodies
(MathJax → cards silently dropped); ordinals are scanned across _all_
fields joined (fabricates cards Anki wouldn't create); missing-ordinal
fallback clones the first card's identity and the `cardIDs` map is keyed by
SRS card id, so one SRS card mapped to several ordinals overwrites earlier
entries and reviews attach to the wrong generated card.

**Fix (per D5), all in `src/anki/anki-package.ts`:**

1. **Regex** (`analyzeClozeOrdinals`):
   `/\{\{c(?<ordinal>[1-9]\d*)::.*?\}\}/gsu` — non-greedy body, `s` flag so
   multi-line clozes match. Mirrors Anki rslib (`rslib/src/cloze.rs`).
   Keep the `c0` exclusion.
2. **Scan scope** (S2): determine the cloze fields from the note type's
   templates — collect field names referenced through a `cloze` filter
   chain in the **question** template (`{{cloze:Text}}`, and filter chains
   like `{{type:cloze:Text}}` — take the last `:`-segment as the field
   name). Run the ordinal scan only over those fields' values, not the
   joined `flds` string.
3. **Missing ordinals** (S1): when a required ordinal has no SRS card with
   that `templateId`, create a **fresh** card (new Anki id from the current
   timestamp-bump scheme, default scheduling, empty
   `applicationSpecificData`) and emit a warning issue
   (`"cloze ordinal N of note … has no card in the package; created a new
card"`). Do **not** clone `noteCards[0]`.
4. **Orphaned SRS cards:** an SRS card whose `templateId` ordinal no longer
   appears in the content is currently dropped with no trace — emit a
   warning issue.
5. **Review mapping:** only real SRS cards enter `cardIDs`
   (srsCardId → ankiCardId, one-to-one); fabricated cards never do. This
   removes the overwrite bug.

**Regression tests:** MathJax cloze `{{c1::\(x^{2}\)}}` produces a card;
multi-line cloze; cloze markers in a non-cloze field produce **no** card;
missing ordinal → fresh card + warning; reviews land on the correct card
(assert via `cid` after export). Port/invert from `03-unit.audit.ts`.

## WP4: First-class media in SrsPackage (F3)

**Problem recap:** `SrsPackage` has no media model; round-trips silently
drop every media file while notes keep referencing them.

**Fix (per D2):**

1. `SrsPackage` gains media management mirroring `AnkiPackage`:
   `addMediaFile(filename, source: string | Buffer | Readable)`,
   `getMediaFile(filename): Readable`, `getMediaFileSize(filename)`,
   `listMediaFiles(): string[]`, `removeMediaFile(filename)`.
   Storage: lazily-created temp dir owned by the package (same pattern as
   `AnkiPackage`), plus an async `cleanup()`. Document the lifecycle
   (callers must `cleanup()`; conversion transfers copies, so source and
   target packages have independent lifetimes).
2. `toSrsPackage`: copy every media file across
   (`srs.addMediaFile(name, ankiPkg.getMediaFile(name))`). This makes
   `toSrsPackage` **async** — a breaking API change (alpha-acceptable;
   agreed direction). Update all call sites, docs, and doc-tests.
3. `fromSrsPackage`: for each SRS media file,
   `ankiPackage.addMediaFile(...)`. Filenames are preserved exactly
   (values in the Anki manifest are arbitrary unicode); duplicate filenames
   throw in `addMediaFile` today — convert that into an error issue + skip
   rather than an exception.
4. Emit a warning when a note references media (`<img src>` / `[sound:]`,
   reuse the regex from `removeUnreferencedMediaFiles`) that is not present
   in the package.

**Regression tests:** round-trip manifest + byte-for-byte content of the
audit package's two media files (one with unicode filename); empty-media
package; SRS-authored package with added media exports correctly.

## WP5: SRS-authored input correctness (F8, F10, F16, S5)

Four small, independent fixes:

1. **F8 — field order:** normalize in `createNote`
   (`src/srs-package.ts`): after the existing set-equality validation,
   reorder `fieldValues` to match `noteType.fields` order before storing.
   Defense-in-depth: `fromSrsPackage` builds `flds` by looking up each
   field name (position fallback) instead of blind array order.
   Test: reversed `fieldValues` → correct `flds` string.
2. **F10 — `BasicAndReverseNote`:** in `src/srs-package.ts`, the second
   template becomes `questionTemplate: "{{Back}}"`,
   `answerTemplate: "{{Front}}"` (mirror the correct
   `basicAndReversedCardModel` in `src/anki/constants.ts`). Test asserts
   the two templates differ and are mutually reversed.
3. **F16 — review id collisions:** give reviews the same bump-until-unique
   loop the other entities have (`while (usedIds.has(id)) id++` — use a
   `Set`, and consider switching the existing `[...map.values()].includes`
   loops to `Set`s while touching this). Test: two same-millisecond reviews
   export without throwing, ids differ by 1.
4. **S5 — non-UUID ids:** in `resolveAnkiId`'s fallback path, validate the
   UUID shape (`/^[0-9a-f]{8}-[0-9a-f]{4}-7[0-9a-f]{3}-…/iu` or a
   pragmatic length/format check). If the id is not a UUIDv7, use the
   existing `generateUniqueIdFromUuid(id)` hash instead of
   `extractTimestampFromUuid` (which hex-parses garbage into tiny ids).
   Test: `"deck-1"`-style id produces a stable, large, positive id.

## WP6: removeUnused warnings (F15)

**Fix (per D4):** change `SrsPackage.removeUnused()` to return a report
(`{ removedDecks, removedNoteTypes, removedNotes }` — returning a value from
a previously-`void` method is non-breaking). Both call sites
(`toSrsPackage` step 7, `fromSrsPackage` pre-conversion) convert every
removed entity into a warning issue naming the entity
(`"Deck 'Default' contains no notes and was not converted"`, …).

**Regression tests:** `toSrsPackage` on `mixed-legacy-2.apkg` still returns
one deck but now with a warning naming `Default`; SRS package with a
card-less note converts with a warning naming the note. Statuses stay
`success` (warnings don't demote status — verify against
`IssueCollector.createResult`).
