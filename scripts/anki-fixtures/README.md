# Anki fixture corpus

Fixtures in `tests/fixtures/anki/corpus/` are generated by **real Anki** (the
`anki` PyPI package wraps the same Rust core as the desktop app), pinned to
the release the wire spec was pinned against (`docs/formats/anki.md`, Anki
26.05 = PyPI `anki==26.5`).

## Files

| File                           | What it is                                                                                                                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `corpus-legacy2.apkg`          | Legacy 2 export (meta version 2, `collection.anki21`)                                                                                                                                            |
| `corpus-v3.apkg`               | Modern export (meta version 3, `collection.anki21b`)                                                                                                                                             |
| `corpus-v3-no-scheduling.apkg` | Modern export without scheduling                                                                                                                                                                 |
| `corpus-v3.colpkg`             | Modern full-collection backup                                                                                                                                                                    |
| `corpus-v3-single-deck.apkg`   | Modern single-deck export (round-trip tests; the Legacy 2 writer supports one deck per package)                                                                                                  |
| `artifacts/`                   | Unit-level dumps: the schema-18 SQLite database, every protobuf config blob (`notetype-*`, `field-*`, `template-*`, `deck-*`, `deck-config-*`), the raw zstd media manifest, and the `meta` file |

All four packages come from the **same collection**, so the legacy/modern
pair is a differential oracle: both must parse to equivalent data.

Coverage: all six stock note types (incl. cloze and image occlusion), subdeck
hierarchy, a filtered deck, two deck presets (one with FSRS params in all
three generations + add-on keys), a per-deck desired-retention override,
image + audio media, hierarchical tags, review history covering revlog types
0–5 (incl. seconds-encoded intervals and manual/FSRS reschedules), per-card
FSRS memory state in `cards.data`, and suspended/buried cards.

## Regenerating

```sh
uv run scripts/anki-fixtures/generate.py
# or without uv:
python3 -m venv .venv-anki && .venv-anki/bin/pip install anki==26.5
.venv-anki/bin/python scripts/anki-fixtures/generate.py
```

Regeneration is **semantically stable, not byte-stable**: entity ids derive
from creation timestamps, so a re-run produces the same entities and content
with different ids. Tests must assert structure and content, never literal
ids. Regenerate only deliberately (e.g. when re-pinning the Anki version),
and re-run the full test suite afterwards.

## Verifying imports with real Anki

```sh
uv run scripts/anki-fixtures/verify.py <package.apkg> [...]
```

Imports each package into a fresh collection and prints a JSON summary
(guids, decks, presets incl. FSRS params, card states, revlog types, media
hashes). Story 1.3.10 wires this into CI against srs-converter's own
outputs. Note: imported stock note types appear with a `+` suffix ("Basic+")
— that is Anki's documented behavior when notetype ids differ between
collections, not a corpus defect.
